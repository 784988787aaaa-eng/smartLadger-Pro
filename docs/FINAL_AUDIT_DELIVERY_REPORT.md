### 1. الملخص التنفيذي

يوثق هذا التقرير أهداف إعادة التصميم والتحقق المطلوب لنوافذ SmartLedger Pro، بما يشمل بطاقة الحساب، وبطاقة الصنف، وسند الصرف، وفواتير المبيعات والمشتريات، وشاشة العمليات. يعتمد التطبيق على .NET 10 وWPF وCommunityToolkit.Mvvm وSQLite وفق وصف المشروع.

**حدود الإثبات:** لا يمكن اعتبار نعومة تحريك النوافذ، أو سلوك التكبير على مختلف درجات DPI، أو مظهر ToolTips أثناء التشغيل، أو سلامة جميع المسارات المحاسبية مُثبتة بمجرد نجاح التجميع. يلزم اختبار واجهة فعلية وتوثيق نتائجه. كذلك يجب التحقق من حالة سير العمل المرتبط تحديدًا برأس الفرع الحالي قبل إعلان صفر أخطاء وصفر تحذيرات.

### 2. مصفوفة التحقق الميداني

| مجال التحقق | معيار القبول | الحالة في هذا التقرير |

### 5. بوابة البناء والاختبارات

قبل الاعتماد النهائي، احفظ أدلة التشغيل الفعلية التالية:

1. رأس الفرع ورمز commit الذي اختُبر.
2. نتيجة `dotnet restore SmartLedger.sln`.
3. نتيجة `dotnet build SmartLedger.sln -c Release --no-restore` مع عدد الأخطاء والتحذيرات.
4. نتيجة `dotnet test tests/SmartLedger.Tests/SmartLedger.Tests.csproj -c Release --no-build --verbosity normal` مع عدد الاختبارات الناجحة والفاشلة والمتجاوزة.
5. نتيجة النشر Windows x64 إن كانت خطوة النشر جزءًا من سير العمل.
6. صور تشغيل للشاشات الست عند حجم عادي وحالة التكبير، مع تسجيل دقة العرض وDPI.
7. اختبارات صريحة للقيم المالية غير الصالحة، والخصم الذي يتجاوز الإجمالي، وعكس الفاتورة وتأثيره على القيود والمخزون.

**قاعدة الاعتماد:** لا تكتب «0 Errors, 0 Warnings» أو «جميع الاختبارات ناجحة» إلا إذا كانت هذه النتائج ظاهرة في سجل CI المطابق للـ commit نفسه. نجاح البناء وحده لا يثبت صحة جميع السيناريوهات المحاسبية أو جودة التفاعل المرئي.
