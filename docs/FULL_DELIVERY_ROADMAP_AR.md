# خطة التسليم الشامل — الدفتر الذكي

> الحالة: خطة عمل حية. لا يُعلن اكتمال أي بند حتى تُنفذ التغييرات وتنجح الاختبارات ذات الصلة، ويُراجع سلوك الواجهة على Windows.

## الهدف
تسليم تطبيق Windows مكتمل وقابل للاستخدام اليومي، شاشةً شاشة ونافذةً نافذة، مع الحفاظ على الهوية البصرية الحالية في WPF وموارد الألوان والخطوط والأنماط، وتحسين السرعة والدقة دون إعادة تصميم عشوائية أو المساس ببيانات المستخدم.

## قواعد التنفيذ
1. كل تغيير يبدأ بفحص مسار الاستخدام الحالي والعقد والنموذج وقاعدة البيانات والاختبارات.
2. لا تُجرى تغييرات على قاعدة بيانات مستخدم حقيقية خلال التطوير أو الاختبار؛ الاختبارات تستخدم قواعد مؤقتة.
3. كل تغيير مخططي يملك ترحيلًا متوافقًا للخلف ويُختبر على قاعدة جديدة وقاعدة سابقة.
4. عمليات الفاتورة وآثار الحساب والمخزون والدفعات تُنفذ ذريًا، وتُحمى من التكرار.
5. لا تُحذف المعاملات المالية المرحلة حذفًا نهائيًا من المسار المعتاد؛ تستخدم آليات إلغاء/عكس موثقة وقابلة للتدقيق.
6. تحفظ القيم التاريخية التي دخلت بها الفاتورة، بما فيها الوحدة ومعامل التحويل والسعر والعملة وسعر الصرف حين يكون ذلك مدعومًا.
7. تبقى واجهات الإدخال اليومية قصيرة وسريعة، وتظهر الحقول المتقدمة عند الحاجة فقط.
8. لا يوصف أي شيء بأنه مكتمل دون دليل: بناء، اختبارات، مراجعة UI على Windows، وفحص حزمة النشر عند انطباقه.

## مسارات التسليم ومعايير القبول

### A. الأساس التقني وصحة البيانات
- [ ] مراجعة مخطط SQLite والترحيلات وفهارس الاستعلامات والقيود.
- [ ] تتبع حفظ/تعديل/عكس البيع والشراء والمرتجعات والمدفوعات والمصروفات والإضافات اليدوية.
- [ ] إثبات ذرية التغييرات المالية والمخزنية، ومنع التكرار عند النقر المزدوج أو إعادة المحاولة.
- [ ] اختبار الدفعات: مجموع الكميات المتبقية يتطابق مع رصيد الصنف وفق الحركات الموثقة.
- [ ] التحقق من الاحتفاظ بالملاحظات والمراجع والتاريخ والوقت في كل مسار ذي صلة.

### B. الوحدات والتسعير
- [ ] وحدة أساسية باسم حر لكل صنف.
- [ ] خيار تفعيل/تعطيل وحدة كبرى اختياريًا، واسم حر ومعامل تحويل واضح.
- [ ] احتساب السعر المقابل تلقائيًا عند إدخال سعر الوحدة الصغرى أو الكبرى، مع إمكان التسعير الخاص لكل وحدة.
- [ ] حفظ وحدة وسعر ومعامل التحويل التاريخي في سطر الفاتورة، وعدم تغيير السجلات القديمة عند تعديل إعداد الصنف.
- [ ] شراء بالوحدة الكبرى وبيع بالصغرى والعكس، واختبارات التقريب والكسور والحدود.

### C. سهولة الإدخال والهوية البصرية
- [ ] جرد كل شاشة ونافذة وحوار وأوامر لوحة المفاتيح.
- [ ] التزام الهوية الحالية وموارد Themes/Styles/Typography/Colors.
- [ ] تقليل الحقول والنقرات، دعم التنقل بالكيبورد والبحث الفوري، والحفاظ على المدخلات عند الخطأ.
- [ ] مراجعة بصرية فعلية على Windows بدقات عرض مختلفة قبل التسليم.

### D. الحسابات وكشوف الحساب
- [ ] عرض «لنا» و«علينا» منفصلين مع رصيد افتتاحي وحركات ورصيد تراكمي وختامي.
- [ ] تفاصيل الشخص والفاتورة والمعاملة وروابط حركة المخزون.
- [ ] البحث والفلاتر الزمنية والنوعية والنصية، بما فيها الملاحظات.
- [ ] عدم اعتبار التحصيل إيرادًا جديدًا أو سداد الدين عملية شراء جديدة.

### E. التقارير والطباعة وPDF/Excel
- [ ] تقارير عامة وتقارير لكل عميل/مورد وصنف ومخزن وحركة.
- [ ] فلاتر فترة مخصصة وفترات سريعة، مع توضيح الفلاتر والفترة في المخرجات.
- [ ] قوالب عربية احترافية متعددة الصفحات، رؤوس جداول متكررة، ترقيم الصفحات، عدم قص النصوص.
- [ ] فاتورة مختصرة ومفصلة وكشف حساب وتقرير مخزون؛ معاينة وطباعة وتصدير واختبارات محتوى الملف.
- [ ] مطابقة الأرقام المصدرة للبيانات المحفوظة وعدم إعادة تسعير العمليات التاريخية.

### F. العملات المتعددة — تصميم تدريجي
- [ ] تحديد العملة الأساسية وعملة كل معاملة وعملة عرض التقرير.
- [ ] تخزين المبلغ الأصلي ورمز/معرّف العملة وسعر الصرف وتاريخه والقيمة المقابلة عند التحويل.
- [ ] منع جمع مبالغ بعملات مختلفة دون تحويل صريح، وعرض الأرصدة منفصلة حسب العملة.
- [ ] اختبار دفعات جزئية وتسويات وفروق صرف وفق سياسة واضحة قبل تفعيل الاستخدام الإنتاجي.

### G. سلة المحذوفات والتدقيق
- [ ] تصنيف السجلات المحذوفة وحفظ بيانات الاستعادة ووقت الحذف وسببه وهوية المستخدم إن توفرت.
- [ ] استعادة آمنة لا تكرر آثار الحساب أو المخزون؛ رفض التعارضات برسالة مفهومة.
- [ ] فصل الحذف المنطقي عن الإلغاء/العكس المحاسبي وعن الحذف النهائي المقيّد.
- [ ] تدقيق شامل للعمليات الحرجة، واختبارات الاستعادة والعكس والتكرار.

### H. الأداء والنسخ الاحتياطي والأمان
- [ ] مراجعة الاستعلامات والفهارس وتحميل البيانات والبحث والقوائم الطويلة.
- [ ] التحقق من النسخ الاحتياطي والاستعادة والتوافق مع قاعدة قديمة قبل أي ترحيل.
- [ ] مراجعة الصلاحيات وحماية الأسرار وسجلات التدقيق ورسائل الخطأ.
- [ ] عدم تشغيل أو تعديل بيانات المستخدم الحقيقية أثناء الاختبارات.

### I. بوابة التسليم النهائي
- [ ] استعادة نظيفة وبناء Release على Windows مع .NET SDK المعتمد.
- [ ] جميع الاختبارات تمر، مع توثيق أي استثناء معروف بدل إخفائه.
- [ ] نشر Windows x64 وتشغيل الحزمة الناتجة على جهاز نظيف أو بيئة اختبار.
- [ ] مراجعة مرئية وتفاعلية لكل شاشة ونافذة وحالة فارغة وخطأ ونجاح.
- [ ] تقرير تسليم نهائي: الميزات المنفذة، الملفات/الترحيلات، نتائج البناء والاختبار، رابط الحزمة، والقيود المتبقية.

## ملاحظات الحالة عند بدء العمل
- المستودع الحالي مبني على WPF/.NET 10 وSQLite، وتوجد بالفعل نماذج عرض وتقارير PDF/Excel وسلة محذوفات واختبارات؛ وجودها لا يثبت اكتمالها.
- توجد تقارير تدقيق سابقة تصف أجزاء بأنها جزئية أو غير متحققة إنتاجيًا؛ يجب إعادة التحقق من الشيفرة والاختبارات الحالية.
- نقطة البداية الحالية: تدقيق فعلي للمسارات الحرجة ثم تنفيذ تغييرات صغيرة قابلة للاختبار على فرع العمل هذا.
